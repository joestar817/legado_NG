# Legado Compose 迁移项目规范

## 适用范围

本规范适用于把既有 XML／View／RecyclerView／Adapter 页面或流程迁移为 Compose 的任务，也适用于修复迁移后的视觉、交互、功能和性能回归。

本次规则来源限定为 2026-08-24 至 2026-08-31 的 Legado 会话复盘；更早会话不计入本次问题清单。复盘对象主要包括“评估 Compose 迁移进度”“梳理书架、发现、订阅迁移进度”“分析 Compose 迁移进度”和“盘点 AI 设置 Compose 迁移”等近期任务。

## 近一周反复出现的问题与项目门禁

| 近期批评／回归 | 暴露的问题 | 强制门禁 |
| --- | --- | --- |
| “不能为了迁移而迁移”；没有授权优化的页面要求“严格按照原样式迁移” | 把渲染技术替换扩大成产品或视觉重构 | 开工前把范围拆成“等价迁移”和“用户逐项批准的偏离”；批准列表之外的结构、文案、控件、顺序、视觉和交互差异必须为零 |
| 用户要求先讨论或先出视觉稿，却直接实现；视觉稿确认后落地几何又自行变化 | 把讨论、提案或局部批准误当成整页实现授权 | “讨论／记住／出稿”阶段不得改 App；只有用户明确“按此实现”后才能编码，选定稿和后续修订共同构成唯一可见基线 |
| 设置子项需要液态材质，却曾被理解成保持普通面；Provider、Skill、模型等管理卡又被错误接成液态 | 按页面层级套材质，没有按组件语义分类 | 迁移契约必须逐项标注 `SETTINGS`、固定白卡、普通透明面或其它已验收角色；禁止整页统一套一个 `surface` |
| “Compose 后白底按钮偏灰的问题好多次了”；模型抽屉白卡和图标颜色也重复出错 | 用动态主题 `surface` 近似旧亮白 Style／Drawable | 旧亮白按钮／白卡必须显式使用对应白底 Variant；同时核对普通浅色主题和强壁纸取色主题下的默认、按下、禁用、选中状态，不得只看默认主题 |
| 迁移对话框时经常把原横线／下划线输入改成大圆角输入框 | 把对话框圆角外壳、表单组件默认造型和字段自身语义混为一体 | 对话框外壳与字段形态分别对照基线；旧横线输入固定使用 `NgFormField(DIALOG_UNDERLINE)` 或等价下划线 Variant，只有旧版原本如此或用户明确批准时才可改成大圆角框 |
| “按钮颜色也不对吧？一定要我每一项都提醒你？”；图标、字重、圆角、密度多轮才对齐 | 没有在交付前逐项审查旧 Style、Drawable 和运行时几何 | 迁移前记录字号、字重、行高、圆角、间距、图标视觉尺寸、触控区、颜色和 Alpha；交付前逐项对比，不把用户实机验收当成第一轮系统性找错 |
| Compose 化后点击“记忆系统／操作权限”崩溃 | 用裸 `Dialog + ComposeView`，缺少 Window 树生命周期 owner | 独立 Window 中的 Compose 必须使用 `ComponentDialog`／正式 Fragment 宿主或显式安装 Lifecycle、SavedState、ViewModelStore owner；所有弹窗入口都要至少做一次打开、操作、关闭回归 |
| Material 默认下拉图标消失后再切换刷新圆环 | 请求开始前未立即发布刷新状态，且直接使用 Material 的两阶段默认指示器 | 迁移前必须对照朗读引擎或同类现役页面的刷新反馈；需要持续反馈时应在回调入口立即设置刷新状态，并使用 `NgPullRefreshIndicatorVariant.SINGLE_SPINNER`，从下拉到请求完成保持同一个指示器；只有原界面确认不需要刷新反馈时才可使用 `showIndicator=false` |
| 默认模板不修改直接保存时列表不新增 | 只验证“编辑后保存”，遗漏 Activity Result 的未修改、取消和返回语义 | 编辑／新建流程必须覆盖默认内容直接保存、修改后保存、返回不保存／取消；返回结果内容、调用方解析、覆盖确认和列表刷新必须形成完整链路 |
| 多文件“AI 扫书”在迁移后点击无反应；用户指出每次都要重新测试全流程 | 把直接传对象改成只传 ID，再从覆盖范围更窄的注册表重查；普通样本掩盖特殊类型 | 保持对象身份和原解析范围；若必须改为 ID，必须证明新解析器覆盖全部类别。单文件、多文件、内置、自定义、系统工作流及嵌套文件节点分别回归“打开→操作→返回” |
| UI 重构期间批量删除从近似即时变成卡顿数秒；用户质疑是否夹带奇怪业务逻辑 | UI 迁移改变或放大业务复杂度，却没有迁移前性能基线 | 高密度列表按真实数量级对比首屏、滚动、搜索／筛选、全选和批量动作耗时；先区分数据／事务耗时与 Compose 重组／布局耗时，性能或业务时序回归即阻断 |
| “我是让你恢复样式，不是恢复到 View”；无引用旧 XML 又被保留 | 把视觉等价误解成技术回退，或没有完成迁移收口 | 已迁移页面在 Compose 层恢复样式；只有无法等价替代的平台内核能力可保留事前声明的最窄互操作。闭环前不提前删旧资源，闭环后必须删除确认不可达的页面、Adapter 和专用 XML |

## 开工前必须提交的迁移契约

### 1. 授权表

至少列出：

- 本批迁移的页面与完整路由范围。
- 只替换渲染技术的区域。
- 用户明确批准重构／优化的逐项清单。
- 必须保留的 View／系统互操作边界及原因。
- 本批明确不处理的相邻功能。

任何新增偏离项都要再次获得用户批准，不能复用一条局部授权覆盖整页或公共组件。

### 2. 页面、状态和动作矩阵

每个页面至少盘点：

- 入口、子页面、抽屉、弹窗、菜单、编辑器、系统选择器和返回路径。
- 默认、空、加载、错误、禁用、选中、半选、全选及配置变化后的状态。
- 点击、整行点击、长按、拖排、滑选、搜索、筛选、刷新、保存、取消、删除、导入、导出和批量动作。
- 导航参数、当前对象、Activity Result、持久化、副作用、列表刷新和回调先后顺序。

### 3. 视觉和几何矩阵

每个可见组件至少记录：

- 旧 XML／Style／Drawable／Adapter 或已验收 Compose 实现的来源。
- 控件数量与顺序、宽高、行高、padding／margin、圆角、描边、Alpha、字号、字重和行数／省略策略。
- 每个输入控件的形态必须单列：下划线／横线、无框、圆角描边或填充框，以及标签、hint、说明文字、单／多行、键盘类型和焦点行为；不得只记录 Dialog 外壳形态。
- 图标资源、视觉尺寸、viewBox／留白、触控区和相邻命中范围。
- 材质角色、前景色、背景色及普通浅色／强壁纸取色／日夜状态。
- 弹层大小、锚点、展开方向、键盘避让、滚动和关闭方式。

迁移后的截图不能作为迁移前基线。需要视觉稿时，选定稿与用户后续标注是实现几何目标，提示词或组件默认值不是验收目标。

### 4. 数据类型和规模矩阵

不能只用最普通、最少量的数据完成验收。按功能选择真实类别和规模，例如：

- 单文件／多文件、根文件／嵌套文件、内置／自定义、普通条目／系统工作流。
- 可编辑／只读、可删除／不可删除、启用／禁用、有能力／无能力。
- 空列表、少量列表、数百条管理列表、长文本、超长名称和多 Tag。
- 正常结果、空结果、异常结果、取消和重复进入。

## 实现门禁

1. Compose 负责渲染和事件回传，业务状态、对象身份、导航参数、回调、事务和副作用默认留在原宿主；任何业务链变化必须单独说明并授权。
2. 精确 NG 组件可表达时必须复用；不能表达时增加作用域最小的命名 Variant，或保留最窄互操作，禁止使用“看起来差不多”的默认 Material 组件。
3. Dialog 外壳可以使用项目规定圆角，但不能把圆角传播成所有内部字段的默认形态；旧下划线输入必须保持下划线、紧凑行高和原有信息密度，不得替换为 Material `OutlinedTextField` 式大圆角框。
4. 不得为修复单页而修改公共默认 Variant；公共变化必须审计全部消费者。
5. `Lazy*` 项使用稳定业务 key，状态不得按位置绑定；组合和滚动路径不得同步访问数据库、文件、Registry、网络或重复解析／排序全量集合。
6. 独立 Compose Window 必须具备完整 owner；编辑器、Dialog、BottomSheet、Popup 和 Activity Result 都按契约验证生命周期与结果语义。
7. 高密度页面优先保证真实数据规模下的信息量和操作效率，禁止用大头像、大圆角卡、大段说明或宽松间距挤压内容。
8. “恢复旧样式”必须在 Compose 渲染层完成，不构成恢复 XML／RecyclerView／Adapter 的授权。

## 验收门禁

### 功能

- 按“入口→详情／编辑→保存／执行→返回刷新”验证每条完整流程。
- 每个动作覆盖成功、失败、取消、返回、重复进入和状态恢复。
- 特殊数据类型不能由普通样本替代；多文件、系统工作流等必须有专门回归。
- 自动化无法覆盖的项必须写成人工验收步骤，不能无声省略。

### 视觉

- 在相同窗口尺寸下对比迁移前基线。
- 至少覆盖普通浅色主题、强壁纸取色主题，以及相关的日夜／透明／液态模式。
- 至少检查默认、按下、禁用、选中、加载、空态、长文本、弹窗展开和键盘状态。
- 未授权的结构、文案、控件、顺序、尺寸、密度、颜色、材质和交互差异必须为零。

### 性能

- 长列表对比首屏、连续滚动、搜索／筛选、全选、批量更新和返回刷新。
- 记录用户可见耗时；明显卡顿、状态先清空后长时间等待、重复刷新、掉帧、内存持续增长或后台任务未释放均不得收口。
- 性能修复不得通过先隐藏内容、减少功能、弱化材质或改变事务／回调时序伪装结果。

### 证据分层

以下证据互不替代：

1. 静态检查：引用、资源、格式、旧入口和死代码审计。
2. 自动化测试：契约、路由、数据类型、状态和回调门禁。
3. `installAppDebug`：编译、打包和安装。
4. 人工流程验收：真实交互、特殊数据和性能体感。
5. 视觉验收：实机几何、材质、主题和状态对比。

用户保留实机验收时，Agent 只安装，不启动、点击、滑动或代替验收。

## 旧实现与完成定义

- 页面／流程闭环前，不提前删除仍用于对照或回退的旧实现。
- 闭环后审计全部路由、Manifest、资源和共享 ID；删除不可达旧页面、Adapter 和专用 XML，不保留隐藏备用入口，也不误删跨模块共享资源。
- 只有完整路由、所有数据类别、关键动作、性能和已授权视觉差异均有证据时，才可写“迁移完成”。
- 已编译安装但未完成人工流程／视觉验收时，只能写“代码完成，待用户验收”。
- 汇报必须列出迁移范围、批准的偏离项、互操作边界、验证结果、性能对比、删除的旧资源、未验收项、已知差异和风险。
