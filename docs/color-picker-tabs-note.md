# 颜色选择：色板 / 色轮 / 透明度（分 Tab 备选）

> 状态：**仅笔记。未锁定，未实现。定稿前不要改代码。**  
> 对照 `legado.my` 祖先的 jaredrummler 选择器，记录 NG 现状与可选演进。  
> 代码（现状）：`NgColorPickerSheet.kt`、`ReadStyleScreen`（`NgGlassSurface` + `readFloatingGlassStyle()`）。  
> 阅读入口：预设编辑器文字/背景/强调色、高亮颜色、页眉页脚颜色、主题种子色。  
> 不在本笔记范围：从当前页背景取色的 `ReadBackgroundColorPicker`（吸色，不是调色）。

## 1. 对照祖先

`legado.my` 阅读配色走 `ColorPickerDialog` `TYPE_CUSTOM`（`BgTextConfigDialog` / `TipConfigDialog` → `ReadBookActivity.onColorSelected`）：

- 连续 HSV：饱和度/明度方块 + 色相条，手指可到任意色
- 点 **选择** 才写入；模态盖在阅读页上
- 正文/背景 **关** alpha
- 主题偏好另开 **预设色** 页（同一库 `TYPE_PRESETS`）

NG 阅读/主题配色换成自绘选择器：

| | 祖先 | 现 NG |
|---|---|---|
| 精度 | 任意 HSV | **104 格**（12 相 × 8 行 + 灰度列）；格外颜色只能敲 hex |
| 确认 | 对话框「选择」 | 点格 / 改 hex **立刻** `onColorChanged` |
| 位置 | 模态 Dialog | 嵌在样式抽屉内（返回 + 重置） |
| 重置 | 无 | 标题栏恢复 |
| Hex | 库内 ARGB | 始终可见 `#AARRGGBB`（`formatNgColor` / `parseNgColor`） |
| Alpha | 阅读关；主题偏好可选 | 仅 `NgColorPickerSheet`（主题）有 `NgAlphaSlider`；**inline 无滑条、无预览盒** |
| 效果预览 | 库内新旧色条 | 只有 48dp 色块；看不到字/底叠在一起的样子 |
| jaredrummler | 阅读 + 主题 + prefs | 只剩 `ColorPreference`；`ReadBookActivity` 的 `ColorPickerDialogListener` 已无阅读配色调用 |

现网 inline 页：

```
←  标题                              [↺]
┌──────────────────────────────────┐
│ 13×8 色板（剩余高度封顶，横屏不挤输入框）│
└──────────────────────────────────┘
[■]  #AARRGGBB
```

色板快、和抽屉一体、横屏仍看得到 hex。代价：不能像祖先那样拖到任意色（除非填 hex）；透明度只能改 hex 的 AA，也看不到字叠在底上的效果。

## 2. 建议（待定稿）

不要把色轮做成第二套弹窗。在现有 chrome（返回 / 标题 / 重置）下用 **分段 Tab** 并列设色方式，**同一份** `currentColor`（含 alpha）。透明度用滑条，效果立刻画在预览盒上。

```
←  文字颜色                          [↺]
┌ 色板 ┬ 色轮 ┐
│                 │
│  （当前 Tab）    │
│                 │
└─────────────────┘
透明度  ────●────────
┌─────────────────┐
│  示例文字 Aa    │  ← 预览盒：当前文字色叠在当前背景上，拖滑条立刻变
└─────────────────┘
[■]  #AARRGGBB     ← 所有 Tab 共用；可当精确入口
```

| 入口 | 用户可见 | 做什么 |
|---|---|---|
| Tab **色板** / Grid | 现 `NgColorPalette` | 快选不透明相；点格即改 RGB，alpha 跟滑条 |
| Tab **色轮** / Wheel | HSV 方块 + 色相条（对齐祖先 `TYPE_CUSTOM`，不必绑 jaredrummler） | 任意色；拖动即改 |
| **透明度** 滑条 | 复用/对齐现有 `NgAlphaSlider`（棋盘底 + 当前色渐变） | 不占 Tab；色板/色轮下面常驻 |
| **预览盒** | 短样本文字 + 背景 | 立刻看字色、底色、透明度叠在一起的效果 |
| Hex / 色块 | `#AARRGGBB` | 粘贴精确值；切 Tab 不丢 |

可选第三 Tab **数值** 只在 hex 行被矮屏挤掉时才需要；默认 hex 常驻。

### 2.1 预览盒怎么画

按**正在改的是哪一项**换盒里的角色，但始终同时出示文字和背景，否则透明度看不出来：

| 正在编辑 | 预览盒 |
|---|---|
| 文字颜色 / 强调色 / 高亮字色 / 页眉字色 | 样本文字用**当前色**（含 alpha）；底用本预设当前背景 |
| 背景颜色 / 高亮底色 | 底用**当前色**（含 alpha，底下衬棋盘或页面底）；样本文字用本预设当前正文色 |

拖色板、色轮、透明度滑条、改 hex，预览盒都立刻更新。阅读页/主题页是否同步重绘仍走现有 `onColorChanged`（Discard 可回滚会话）。

### 2.2 建议约束（同样未锁定）

1. **一份颜色状态。** 切 Tab 只换控件，不重置、不另开确认。
2. **即改即预览。** 不要回到祖先那种必须点「选择」才生效。
3. **高度预算。** `EditorPageHeight` / 主题抽屉 50–60% 高度；色板/色轮按剩余高度封顶，滑条 + 预览盒 + hex 必须仍可见。
4. **透明度滑条在 Tab 下面、与色板/色轮无关。** 主题 sheet 已有的 alpha 滑条与 inline 合并为同一控件，不要两套手感。
5. **共享实现。** `NgInlineColorPicker` 与 `NgColorPickerSheet` 用同一套 Tab + 色轮 + 滑条 + 预览盒。
6. **吸色另留。** 浮动窗「从背景取色」仍是全屏吸色，不塞进这个 Tab。

未锁定：

- 是否记住上次用的 Tab
- 色轮用方块 SV + 条，还是真圆轮（方块更接近祖先、也更好点）
- **阅读正文/背景要不要真把 alpha 写入 `ReadBookConfig`**（今日存储基本当不透明用；预览盒可以先演示 alpha，落盘是否写 AA 要单独定）
- 预览盒高度（建议一行样本文字，约 36–44dp，避免再挤色板）
- 是否从工程里拿掉未再打开的 `ColorPickerDialogListener`（阅读路径）

## 4. 预设抽屉：面板透明度（偷看底下的正文 / 调整）

颜色选择器里的透明度滑条改的是 **正在编辑的色**。另需要一条滑条改 **整扇阅读样式抽屉** 的玻璃，好透过面板看页上的字色、字号、间距。

现状：`ReadStyleScreen` 根容器是 `NgGlassSurface(style = readFloatingGlassStyle())`，透明度跟阅读浮动栏共用 `ReadFloatingAppearanceState.transparencyPercent`（预设里「浮动外观」那条）。抽屉上 **没有** 单独的偷看控件；把浮动外观拖透明，菜单也会一起变。

建议（待定稿）：在抽屉 **chrome** 上加一条 **面板透明度**，只影响这扇窗，立刻透过玻璃看阅读页。

```
┌ 预设 ┬ 调整 ┬ 高亮 ┬ 默认 ┐     ← 顶栏 Tab，不动
│                         │
│  （当前页内容）           │
│                         │
│  面板  ────●────────     │     ← 建议：底栏上方，拇指够得到
│  [放弃]          [完成]  │     ← 现有 ReadStyleSessionBar
└─────────────────────────┘
     ↑ 透过玻璃看到正文
```

**放底下，不要放顶上。** Tab 已经在顶；调整页中部还有字号等滑条。顶上再加一条容易当成设置项。`ReadStyleSessionBar`（放弃/完成）每页都在，包括编辑/取色子页——滑条贴在它 **上面**，所有页都能偷看，又不和确认按钮抢一行。

这条滑条：

| 要 | 不要 |
|---|---|
| 只改本扇 `NgGlassSurface` 的透明度 | 写入 `readFloatingTransparency` / 浮动外观 |
| 拖动立刻变玻璃（看到底下字和版面） | 跟颜色 alpha、预览盒混成一条 |
| 留不透明下限（控件仍可读，大约不要全透） | 拖到 100% 透明导致 Tab/完成点不到 |
| 建议 **仅本次打开有效**；关掉抽屉恢复 | 默认当成一条新的全局阅读设定 |

未锁定：关掉后是否记住上次面板透明度（独立 pref 可以，仍不要并进浮动外观）；文案用「面板」还是「窗口」。
